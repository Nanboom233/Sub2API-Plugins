# Adapt Plugins to Sub2API v0.2.23, Add Model-Control Defaults, and Fix Quota Scheduling, Probe Memoization, Identity CAS, and SIWC Admission

## Goal

Deliver `plugins/codex-candy-eval` and `plugins/sub2api-quota-extension` on Sub2API `v0.2.23` (Go `1.27.4`) with `gpt-6.1-terra` and `gpt-6.2-sol` in the default model-control removal list, while preserving standalone plugin independence and all verified task behaviors:
1. Synchronize quota exhaustion and recovery from `GET /v1/usage` and custom scripts into native Sub2API scheduling decisions.
2. Share unsupported endpoint memoization across automatic `GET /v1/usage` and scheduled `GET /v1/sub2api/billing` probes without blocking manual probes.
3. Guard asynchronous quota, expiration, memoization, and inspection writes with narrow atomic identity checks, and preserve concurrent state during ordinary saves and partial quota responses.
4. Allow SIWC row, selection, and batch checks on locally rate-limited accounts without clearing rate limits or changing other evaluation tabs.

## Requirements

1. **Dated and undated quota exhaustion**: Pause dated window exhaustion (`Utilization >= 100` with future `ResetsAt`) until the latest future `ResetsAt` with reason `apikey_quota_window_exhausted`. Mark undated exhaustion (`Balance <= 0` or `Utilization >= 100` without future `ResetsAt`) in `accounts.extra.apikey_quota_exhausted` (recording balance source in `apikey_quota_balance_exhausted`) so `IsQuotaExceeded` returns `true`.
2. **Partial and overlapping quota recovery**: Merge reported balance and window observations with the locked database row inside `UpdateAPIKeyQuotaState`. Clear a source's exhaustion when a later response reports that source healthy, even after an overlapping same-identity write. Retain exhaustion and active dated pauses from unreported sources without inferring legacy balance blocks.
3. **Single, bulk, and ordinary account saves**: Strip cleared managed quota keys via JSONB key removal (without JSON `null` values) and clear `apikey_quota_%` pauses when single or bulk edits change probe identity (`platform`, `type`, `credentials`, `proxy_id`, routing fields) or `quota_script`, or on administrator quota reset, while preserving non-quota pauses and syncing Redis scheduler snapshots immediately. During ordinary saves with unchanged identity and script, merge current database quota state and preserve unedited `expires_at` in one locked native transaction.
4. **Atomic post-network identity CAS**: Guard asynchronous writes from `GET /v1/usage`, `ExecuteQuotaScript`, and `GET /v1/sub2api/billing` memoization (`apikey_quota_*`, `TempUnschedulableUntil`, `ExpiresAt`, `apikey_usage_unsupported_identity`) with an atomic compare-and-swap check over `platform`, `type`, full `credentials`, `proxy_id` plus hydrated proxy target, and normalized `quota_script`. Update the caller's in-memory `Account` only after transaction commit.
5. **Scheduler visibility and probe memoization**: Retain `apikey_quota_*` keys in `filterSchedulerExtra` and evaluate saved window snapshots in `EvaluateAccountSchedulingThreshold`. Store `apikey_usage_unsupported_identity` after HTTP 404, 405, 501, non-OpenAI official domains, or invalid 2xx bodies (`<= 64 KiB`). Skip automatic `GET /v1/usage` (`!forceProbe`) and scheduled `GET /v1/sub2api/billing` (`requireEnabled == true`) when the digest matches `upstreamBillingProbeIdentity(account)`, while allowing manual refreshes and manual billing probes.
6. **Evaluation narrow persistence, native protocols, and UI refresh**: Persist inspection verdicts and model removals through narrow conditional `UpdateCodexInspectionState` without overwriting concurrent credentials, status, priority, quota keys, or opt-outs (`codex_eval_inspection_enabled == false`). Reuse native Sub2API senders, stream completion (`apicompat.FinalizeAnthropicResponsesStream` and native Gemini completion), and Antigravity API-key Gemini/Claude protocol routing. Reload `/api/v1/admin/accounts` when an inspection round finishes.
7. **SIWC local rate-limit admission**: Ignore local `rate_limit_reset_at` only for `siwc-` action eligibility (row start, checkbox selection, select-all, batch targets, and selection retention across refresh) in `plugins/codex-candy-eval/patches/0006-evaluation-ui.patch`. Keep the displayed rate-limit tag, persisted rate-limit state, real upstream HTTP 429 `limited` classification, other account restrictions, and Candy/Fingerprint/Pelican blocking unchanged.
8. **Evaluation model-control default removal list**: Set default `degraded_remove_models` to `["gpt-6.1-sol", "gpt-6-sol", "gpt-5.6-sol", "gpt-6-astra", "gpt-6.1-terra", "gpt-6.2-sol"]` in `plugins/codex-candy-eval/patches/0005-inspection.patch:941`, update matching default expectations in `tests/test_service_codex_inspection_settings_test.go:105`, `tests/test_ui.cjs:19`, and `.trellis/spec/backend/native-inspection.md:58`, and preserve order, deduplication, and explicit empty-list `[]` behavior.
9. **Simplicity and plugin independence**: Keep both plugins independently usable with zero cross-plugin production symbols, zero unnecessary wrapper types or action enums, and zero duplicate DTO or `AccountBulkUpdate` scheduling fields.
